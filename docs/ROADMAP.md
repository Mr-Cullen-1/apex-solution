# Roadmap

## Phase 0 — Foundation

- Framework, TypeScript, linting, and build setup
- Permanent project guidance and documentation
- Brand tokens and base accessibility behavior
- Typed, centralized content/configuration
- Header, utility bar, footer, mobile conversion bar, and UI primitives
- Root metadata, sitemap, and robots foundation

## Phase 1 — Homepage and navigation

- [x] Final responsive header, mobile navigation, and accessible mega menu
- [x] Homepage visual system and all priority homepage sections
- [x] Problem-first service selector with useful destinations
- [x] Centralized temporary image direction and optimized responsive delivery
- [x] Initial FAQ and review components using verified-content safeguards
- [ ] Final responsive browser QA and production photography approval

## Phase 2 — Services and conversion

- Services index and service-detail templates
- Multi-step booking wizard with validation
- Emergency, membership, financing, offers, and contact experiences
- Analytics event plan and consent requirements

## Phase 3 — Local authority and content

- About, team, reviews, projects, careers, and service-area templates
- Resources index and article route
- Route-specific metadata, canonical URLs, and validated structured data
- Approved CMS model and migration adapter

## Phase 4 — Integration and launch

- CRM/scheduling integration and failure handling
- Production business data, legal copy, and accessibility audit
- Performance budgets, cross-browser/device QA, monitoring, redirects, and launch checklist

## Recommended Phase 1 acceptance criteria

The homepage and navigation should match the approved brand direction at mobile, tablet, desktop, and large desktop; all interactions must be keyboard accessible; every CTA must resolve to an intentional destination; content must be verified or explicitly marked; lint, typecheck, build, and browser QA must pass.
